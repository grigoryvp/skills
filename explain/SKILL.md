Расскажи подробно про замечание $ARGUMENTS, чтобы я мог понять в чем проблема
без чтения кода и погружения в контекст. Рассказ составь из следующих частей,
каждую часть отдели от следующей одной пустой строкой:

1. Контекст: о какой части проекта замечание, какие действующие лица.
   Используй необходимый минимум прозы, необходимый, чтобы познакомить
   читателя со всеми действующими лицами, которые будут присутствовать
   в описании замечания. Пример:

   ```
   **Контекст**: проект — приложение для визуализации транзакций пользователей
   в сети TON. Деплой в три кластера Kubernetes, для распределения задач
   используется Kafka, для синхронизации PostgreSQL с мастером и асинхронными
   репликами.
   ```

2. Краткое описание замечания. Пример:

   ```
   **Замечание**: так как реплики асинхронные, то в случае отказа дата-центра
   в Kafka могут возникнуть дубли.
   ```

3. Минимальная последовательность шагов, при которой возникнет дефект. Пример:

   ```
   **Пример**:
   1. Под в дата-центре 1 пишет сообщение в Kafka и обновляет метаинформацию
      в PostgreSQL.
   2. Дата-центр 1 теряет связь с дата-центрами 2 и 3.
   3. Kafka успевает получить кворум, PostgreSQL не успевает реплицироваться.
   4. Под в дата-центре 2 видит старую метаинформацию в PostgreSQL и повторно
      пишет сообщение в Kafka.

4. Если для замечания есть возможные решения, то каждое решение начинай с
   эмодзи "⚙️", затем номер решение (если более одного решения) и далее
   краткое описание решения (может занимать более одной строки).
   - Пример с одним возможным решением:
     ```
     ⚙️ Поменять реплику на синхронную.
     ```
   - Пример с двумя возможными решениями:
     ```
     ⚙️ 1. Поменять реплику на синхронную.
     ⚙️ 2. Использовать дополнительный топик в Kafka для синхронизации.
     ```
