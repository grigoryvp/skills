Оцени замечания к merge request двумя независимыми ревьюерами параллельно,
затем объедини их оценки. URL замечаний:

$ARGUMENTS

Промпт ревью: `${CLAUDE_SKILL_DIR}/comment-review.md`.
JSON-схема оценки: `${CLAUDE_SKILL_DIR}/comment-review.schema.json`.
Результаты складывай в scratchpad-директорию сессии `$OUT`.

## Шаг 1. Проверка рабочей директории

Выполни fetch репозитория в рабочей директории.

Обновил локальную дефолтную ветку.

Проверь, что в рабочей директории клонирован проект, к которому замечание,
текущая ветка та же, к которой замечание и текущая ветка содержит все
изменения из upstream. Если это не так — сообщи и заверши выполнение скилла.

## Шаг 2. Запусти обоих ревьюеров и дождись их

Запусти команду ниже одним вызовом shell с таймаутом 30 минут и дождись
результата выполнения:

```sh
set --
i=0
for url in $(echo '$ARGUMENTS' | tr ',' ' '); do
  i=$((i + 1))
  d="$OUT/$i"
  mkdir -p "$d"
  echo "$i: $url"
  printf 'REVIEW_URL=%s\n' "$url" \
    | uvx --from jinja2-cli jinja2 --format=env --strict \
      "${CLAUDE_SKILL_DIR}/comment-review.md" \
    > "$d/comment-review-prompt.md"

  start=$(date +%s)
  {
    codex exec -s workspace-write --ephemeral \
      -c sandbox_workspace_write.network_access=true \
      --output-schema "${CLAUDE_SKILL_DIR}/comment-review.schema.json" \
      -o "$d/codex-review.json" - < "$d/comment-review-prompt.md" \
      > "$d/codex-review.log" 2>&1
    echo "$i codex exit: $?, time: $(( $(date +%s) - start ))s"
  } &
  set -- "$@" $!

  {
    claude -p --output-format stream-json --verbose \
      --json-schema "$(cat "${CLAUDE_SKILL_DIR}/comment-review.schema.json")" \
      < "$d/comment-review-prompt.md" \
      > "$d/claude-review.jsonl" 2> "$d/claude-review.log"
    echo "$i claude exit: $?"
  } &
  set -- "$@" $!
done

wait "$@"
echo "claude effort: ${CLAUDE_CODE_EFFORT_LEVEL:-default}"
```

Шаги 3–5 выполни для каждого URL по порядку, считая `$OUT` директорией
`$OUT/N` N-го URL. Ответы для разных URL отдели пустой строкой.

## Шаг 3. Проверь результаты ревьюеров

Если один из ревьюеров завершился с ошибкой или его JSON-файл отсутствует или
пуст, покажи хвост лога и продолжай только с оценкой второго ревьюера,
явно это отметив.

Если оба ревьюера завершились с ошибками или их JSON-файлы отсутствуют или
пусты, то напиши об этом и заверши ревью.

Оценка claude — поле `structured_output` в последней строке
`$OUT/claude-review.jsonl` (`"type": "result"`); если `is_error` равно
`true` или поля `structured_output` нет, считай это ошибкой ревьюера.

## Шаг 4. Объедини результаты

Объедини одинаковые варианты исправления в один. Отсортируй варианты от
лучшего к худшему, выше — предложенные обоими ревьюерами.

## Шаг 5. Ответ

Значения `verdict` в ответе: `fix` — «править», `optional` — «опционально»,
`done` — «уже исправлено», `reject` — «не править».

Покажи оценку на русском языке. Она состоит из перечисленных ниже элементов,
не более одного элемента на строке:

- Номер замечания в виде эмодзи 1️⃣, 2️⃣ или 3️⃣, затем краткое саммари замечания
  жирным шрифтом, затем в скобках severity — все вместе до 80 символов.
  Пример:
  ```
  1️⃣ Сервис падает при ошибке в настройках (major)
  ```

- Ноль, одна или две строки `file:line` из ответов ревьюеров. Если оба
  ревьюера прислали разные `file:line`, то используй две строки и после
  каждой в скобках укажи ревьюера.

- Эмодзи "✍️", далее краткое описание замечания и в какой ситуации
  проявляется, по мнению автора замечания.

- Одна или две оценки ревьюеров. Перед каждой оценкой соответствующая ей
  эмодзи: "✅" если замечание уже исправлено, "🛠️" если ревьюер предлагает
  исправить замечание, "❌" если ревьюер предлагает не править замечание,
  "🤔" если ревьюер считает исправление опциональным. Если оценки ревьюеров
  одинаковые, то суммаризируй обе оценки в одну. Если оценки ревьюеров
  различаются, то приведи обе.

- Если есть варианты исправления, то каждый вариант начинай с эмодзи "⚙️",
  затем номер варианта (если более одного варианта) и далее краткое описание
  варианта (может занимать более одной строки).

- Если есть варианты исправления, то каждый вариант начинай с
  эмодзи "⚙️", затем номер варианта (если более одного варианта) и далее
  краткое описание варианта (может занимать более одной строки). Если
  вариантов более одного, то перечисли их от наиболее подходящего к наименее
  подходящему и после перечисления добавь пункт с эмодзи "📌", где кратко
  сформулируй, какой из предложенных вариантов ты рекомендуешь и почему.
  Рекомендуемый вариант может отличаться от первого в сортировке.
  Используй несколько "⚙️" с нумерацией только если есть более одного
  **разного** варианта; если один или несколько вариантов содержит
  дополнительные шаги, например "добавить тест", то такие шаги должны быть
  частью прозы соответствующих вариантов, а не отдельными пунктами.

  - Пример с одним вариантом:
    ```
    ⚙️ Значения по умолчанию для настроек.
    ```
  - Пример с двумя вариантами:
    ```
    ⚙️ 1. Значения по умолчанию для настроек.
    ⚙️ 2. Писать в лог не исключение, а информацию о некорректных настройках.
    ```
  - Пример неправильного ответа с дополнительным шагом отдельным пунктом:
    ```
    ⚙️ 1. Значения по умолчанию для настроек.
    ⚙️ 2. Добавить тест.
    ```
  - Пример правильного ответа с дополнительным шагом в прозе варианта:
    ```
    ⚙️ Значения по умолчанию для настроек, тест.
    ```

## Шаг 6. Статистика ревьюеров

В конце ответа после пустой строки добавь две строки, по одной на ревьюера:
модель, effort, суммарное время работы и суммарное количество токенов
по всем URL  Для упавшего ревьюера покажи то, что удалось узнать, остальное
замени на "?". Пример:

```
🤖 claude-opus-5-5, high, 4м 12с, 2.1M
🤖 gpt-6.1-sol, high, 3м 5с, 1.2M
```

Откуда брать значения:
- claude, последняя строка `$OUT/claude-review.jsonl` (`"type": "result"`):
  модель — ключ в `modelUsage` с наибольшим `costUSD`; время —
  `duration_ms`; токены — сумма `inputTokens`, `outputTokens`,
  `cacheReadInputTokens`, `cacheCreationInputTokens` по всем моделям в
  `modelUsage`. Effort — строка `claude effort:` из вывода шага 2.
- codex, `$OUT/codex-review.log`: модель и effort — строки `model:` и
  `reasoning effort:` в заголовке лога; время — `time:` из вывода шага 2;
  токены — число после строки `tokens used` в конце лога.
