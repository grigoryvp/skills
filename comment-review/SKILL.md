Оцени замечание к merge request двумя независимыми ревьюерами параллельно,
затем объедини их оценки. URL замечания:

$ARGUMENTS

Промпт ревью: `${CLAUDE_SKILL_DIR}/comment-review.md`.
JSON-схема оценки: `${CLAUDE_SKILL_DIR}/comment-review.schema.json`.
Результаты складывай в scratchpad-директорию сессии `$OUT`.

## Шаг 1. Запусти обоих ревьюеров и дождись их

Запусти команду ниже одним вызовом shell и дождись результата выполнения:

```sh
codex exec -s read-only --ephemeral \
  --output-schema "${CLAUDE_SKILL_DIR}/comment-review.schema.json" \
  -o "$OUT/codex-review.json" - < "${CLAUDE_SKILL_DIR}/comment-review.md" \
  > "$OUT/codex-review.log" 2>&1 &
codex_pid=$!

claude -p \
  --json-schema "$(cat "${CLAUDE_SKILL_DIR}/comment-review.schema.json")" \
  < "${CLAUDE_SKILL_DIR}/comment-review.md" \
  > "$OUT/claude-review.json" 2> "$OUT/claude-review.log" &
claude_pid=$!

wait "$codex_pid"; echo "codex exit: $?"
wait "$claude_pid"; echo "claude exit: $?"
```

## Шаг 2. Проверь результаты ревьюеров

Если один из ревьюеров завершился с ошибкой или его JSON-файл отсутствует или
пуст, покажи хвост лога и продолжай только с оценкой второго ревьюера,
явно это отметив.

Если оба ревьюера завершились с ошибками или их JSON-файлы отсутствуют или
пусты, то напиши об этом и заверши ревью.

## Шаг 3. Объедини результаты

1. Если `verdict` совпадает, пометь оценку источником `оба`, иначе укажи
   оценку каждого ревьюера.
2. Объедини одинаковые варианты исправления в один. Отсортируй варианты от
   лучшего к худшему, выше — предложенные обоими ревьюерами.

## Шаг 4. Ответ

Значения `verdict` в ответе: `fix` — «править», `optional` — «опционально»,
`done` — «уже исправлено», `reject` — «не править».

Покажи оценку на русском языке. Она состоит из перечисленных ниже элементов,
не более одного элемента на строке:

- Краткое саммари замечания жирным шрифтом, до 80 символов. Примеры:
  ```
  **Сервис падает при ошибке в настройках**
  **Лишняя аллокация в цикле**
  ```
- Ноль, одна или две строки `file:line` из ответов ревьюеров. Если оба
  ревьюера прислали разные `file:line`, то используй две строки и после
  каждой в скобках укажи ревьюера.
- Эмодзи "✍️", далее краткое описание замечания и в какой ситуации
  проявляется, по мнению автора замечания.
- Одна или две оценки ревьюеров. Перед каждой оценкой соответствующая ей
  эмодзи: "✅" если замечание уже исправлено, "🛠️" если ревьюер предлагает
  исправить замечание, "❌" если ревьюер предлагает не править замечание,
  "🤔" если ревьюер считает исправление опциональным. Если оценки ревьюеров
  одинаковые, то суммаризируй обе оценки в одну. Если оценки ревьюеров
  различаются, то приведи обе.
- Если есть варианты исправления, то каждый вариант начинай с эмодзи "⚙️",
  затем номер варианта (если более одного варианта) и далее краткое описание
  варианта (может занимать более одной строки).
  - Пример с одним вариантом:
    ```
    ⚙️ Значения по умолчанию для настроек.
    ```
  - Пример с двумя вариантами:
    ```
    ⚙️ 1. Значения по умолчанию для настроек.
    ⚙️ 2. Писать в лог не исключение, а информацию о некорректных настройках.
    ```
