Проведи ревью изменений в текущей ветке двумя независимыми ревьюерами
параллельно, затем объедини их замечания.

Промпт ревью: `${CLAUDE_SKILL_DIR}/code-review.md`.
JSON-схема замечаний: `${CLAUDE_SKILL_DIR}/code-review.schema.json`.
Результаты складывай в scratchpad-директорию сессии `$OUT`.

## Шаг 1. Актуализируй репозиторий

Выполни fetch репозитория в рабочей директории.

Обновил локальную дефолтную ветку.

Проверь, что текущая ветка содержит все изменения из upstream. Если это
не так — сообщи и заверши выполнение скилла.

## Шаг 2. Запусти обоих ревьюеров и дождись их

Запусти команду ниже одним вызовом shell с таймаутом 30 минут и дождись
результата выполнения:

```sh
start=$(date +%s)
codex exec -s read-only \
  --output-schema "${CLAUDE_SKILL_DIR}/code-review.schema.json" \
  -o "$OUT/codex-review.json" - < "${CLAUDE_SKILL_DIR}/code-review.md" \
  > "$OUT/codex-review.log" 2>&1 &
codex_pid=$!

claude -p --output-format stream-json --verbose \
  --json-schema "$(cat "${CLAUDE_SKILL_DIR}/code-review.schema.json")" \
  < "${CLAUDE_SKILL_DIR}/code-review.md" \
  > "$OUT/claude-review.jsonl" 2> "$OUT/claude-review.log" &
claude_pid=$!

wait "$codex_pid"; rc=$?
echo "codex exit: $rc, time: $(( $(date +%s) - start ))s"
wait "$claude_pid"; echo "claude exit: $?"
echo "claude effort: ${CLAUDE_CODE_EFFORT_LEVEL:-default}"
```

## Шаг 3. Проверь результаты ревьюеров

Если один из ревьюеров завершился с ошибкой или его JSON-файл отсутствует или
пуст, покажи хвост лога и продолжай только с замечаниями второго ревьюера,
явно это отметив.

Если оба ревьюера завершились с ошибками или их JSON-файлы отсутствуют или
пусты, то напиши об этом и заверши ревью.

Замечания claude — поле `structured_output` в последней строке
`$OUT/claude-review.jsonl` (`"type": "result"`); если `is_error` равно
`true` или поля `structured_output` нет, считай это ошибкой ревьюера.

## Шаг 4. Объедини результаты

1. Объедини одинаковые замечания из двух источников в одно, оставив
   наибольший severity. Пометь каждый источником: `claude`, `codex` или
   `оба`.
2. Отсортируй по важности: сначала severity, при равном — совпадение у обоих
   ревьюеров выше.

## Шаг 5. Ответ

Напиши общее количество найденных замечаний (`blocker`, `major`, `minor`).

Если замечания есть, покажи не больше трёх, начиная от самого важного,
на русском языке. Каждое замечание состоит из перечисленных ниже элементов,
не более одного элемента на строке:

- Номер замечания в виде эмодзи 1️⃣, 2️⃣ или 3️⃣, затем краткое саммари замечания
  жирным шрифтом, затем в скобках ревьюер и severity — все вместе до 80
  символов. Пример:
  ```
  1️⃣ Сервис падает при ошибке в настройках (codex, major)
  ```
- `file:line`
- Эмодзи "✍️", далее краткое описание недостатка и в какой ситуации
  проявляется.
- Если ревьюеры вернули возможные решения, то каждое решение начинай с
  эмодзи "⚙️", затем номер решение (если более одного решения) и далее
  краткое описание решения (может занимать более одной строки).
  - Пример с одним возможным решением:
    ```
    ⚙️ Значения по умолчанию для настроек.
    ```
  - Пример с двумя возможными решениями:
    ```
    ⚙️ 1. Значения по умолчанию для настроек.
    ⚙️ 2. Писать в лог не исключение, а информацию о некорректных настройках.
    ```
- Если это замечание не последнее, то добавь одну пустую строку, чтобы
  замечания были визуально отделены друг от друга.

## Шаг 6. Статистика ревьюеров

В конце ответа после пустой строки добавь две строки, по одной на ревьюера:
модель, effort, время работы, usage и использование лимитов подписки —
сначала 5-часового, затем недельного. Для упавшего ревьюера покажи то, что
удалось узнать, остальное замени на `?`. Перед процентом лимита ставь
эмодзи цвета: 🟢 до 30% включительно, 🟠 до 80% включительно, 🔴 выше 80%.
Пример:

```
🤖 claude-opus-5-5, high, 4 мин 12 с, $1.23, 2.1M, 🟢25% и 🟠74%
🤖 gpt-6.1-sol, high, 3 мин 5 с, 1.2M, 🟠67% и 🟠75%
```

Откуда брать значения:
- claude, последняя строка `$OUT/claude-review.jsonl` (`"type": "result"`):
  модель — ключ в `modelUsage` с наибольшим `costUSD`; время —
  `duration_ms`; usage — `total_cost_usd` и сумма `inputTokens`,
  `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens` по всем
  моделям в `modelUsage`. Effort — строка `claude effort:` из вывода шага 2.
  Лимиты — `rate_limit_info.unifiedWindows.five_hour.utilization` и
  `.seven_day.utilization` (доля от 1) из последней строки с
  `"type": "rate_limit_event"`.
- codex, `$OUT/codex-review.log`: модель и effort — строки `model:` и
  `reasoning effort:` в заголовке лога; время — `time:` из вывода шага 2;
  usage — число после строки `tokens used` в конце лога. Лимиты —
  `rate_limits.primary.used_percent` (5 часов) и
  `rate_limits.secondary.used_percent` (неделя) из последнего события с
  `rate_limits` в файле сессии `~/.codex/sessions/**/rollout-*<id>.jsonl`, где
  `<id>` — строка `session id:` из заголовка лога.
